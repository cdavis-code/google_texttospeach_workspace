# AGENTS.md - google_texttospeech Workspace

## Project Overview

Dart monorepo (Dart SDK ^3.8.0) providing a native Dart interface to the
Google Cloud Text-to-Speech REST API v1 (`voices.list`, `text:synthesize`).
Uses Dart workspaces + Melos for package management. Structure mirrors the
`yt_workspace` reference project (dio + retrofit + json_serializable,
service classes over Retrofit clients, one command group per resource in
the CLI).

## Packages

| Package | Purpose |
|---------|---------|
| `packages/google_texttospeech` | Core library - Cloud Text-to-Speech v1 API |
| `packages/google_texttospeech_cli` | `tts` CLI tool |
| `packages/google_texttospeech_js` | dart2js + TypeScript/npm bindings → `@unngh/google-texttospeech` |

`google_texttospeech_js` is a Dart workspace member (so `melos bootstrap` /
`melos run analyze` cover its Dart interop) but is **excluded from `melos run
test`** (its tests are vitest) and builds via `npm run build` (`scripts/build.sh`
→ dart2js, then `tsup`). Its `node_modules`/`build`/`dist` are gitignored.

`third_party/` is a local-only copy of the reference repo used as the port
source; it is gitignored, not product code.

## Commands

```sh
# Setup
melos bootstrap              # Install all deps (recommended)

# Code generation (retrofit_generator + json_serializable)
melos run build              # Runs build_runner where build.yaml exists

# Verify (run in this order)
melos run analyze            # dart analyze --fatal-infos
melos run format-check       # Check formatting
melos run lint:all           # analyze + format-check

# Tests
melos run test               # Runs dart test in packages with test/ dirs
```

## Key Conventions

- **Workspace resolution**: both packages use `resolution: workspace` in pubspec.yaml
- **Generated files**: `*.g.dart` (json_serializable/retrofit) are excluded from analysis
- **Codegen**: `retrofit_generator` + `json_serializable` via build_runner;
  `build.yaml` sets `explicit_to_json: true` so nested models serialize eagerly
- **Enum wire values**: Dart enums with `@JsonValue('SCREAMING_CASE')`;
  forward-compat via `@JsonKey(unknownEnumValue: <Enum>.fallback)` on nullable fields
- **API surface**: v1 only, 2 methods. Long-running operations / batch synthesis
  are intentionally NOT implemented (see design spec)
- **Melos 8 scripts**: use `exec: {command: ...}`, not the removed `run`+`exec` combo
- **meta.dart**: generated by `melos run meta` from pubspec.yaml; do not hand-edit

## Authentication (library design)

- `GoogleTts.withApiKey()` — default; `GOOGLE_TTS_API_KEY` env / `./.env` / explicit
- `GoogleTts.withOAuth()` — bearer interceptor over stored `oauth2` credentials;
  the only v1 scope is `cloud-platform` (project-wide). Plaintext token files in
  `~/.tts/`, chmod 600. Document the trade-offs before steering users to OAuth.
- `GoogleTts.withGenerator()` — caller-supplied token (secret manager / ADC);
  nothing is persisted by this library
- Env var prefix: `GOOGLE_TTS_*`; `GOOGLE_TTS_DISABLE_DOTENV=1` disables `.env` lookup

## Analysis

- Includes `package:lints/recommended.yaml`
- Strict inference and raw types enabled
- Generated files excluded: `**/*.g.dart`

## CI

`.github/workflows/dart.yml`: runs on push/PR to `main`. Bootstraps melos,
runs codegen, `dart analyze --fatal-infos`, `dart format --set-exit-if-changed`,
and `dart test`.

## Releasing

```sh
cd packages/google_texttospeech && dart pub publish
cd packages/google_texttospeech_cli && dart pub publish
```

Tag with melos-style `google_texttospeech-v*` / `google_texttospeech_cli-v*`
when cutting releases.
